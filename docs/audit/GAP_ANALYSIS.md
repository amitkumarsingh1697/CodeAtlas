## 5. Gaps that are not in the PRD but matter commercially

1. **ArchLens has no place in the PRD.** The package treats ArchLens as "the visualization/exploration experience" (doc 01 §11, master prompt §7.2), but in the repo ArchLens is a Claude Code skill and the UI is CodeAtlas web. See conflict C-03 in [DOCUMENTATION_RECONCILIATION.md](DOCUMENTATION_RECONCILIATION.md).
2. **The Investigate workflow (patching and merging) is out of scope for the assessment** (PRD §10 "automatic code modification as a core assessment feature" is out of scope). It works and is well tested; keep it, but do not put it in the assessment demo.
3. **No way to run CodeAtlas inside a customer environment without a developer setup.** This blocks the customer-operated assessment more than any analysis gap.
